Self-Amending Threshold Authority

Denotational design report · 3 November 2026

Self-Amending Threshold Authority

An off-chain system that authorizes an action when enough of a committee approves it. Zero-knowledge proofs (ZK), fully homomorphic encryption (FHE) and multi-party computation (MPC) keep each ballot private. The system changes its own rules through the same quorum process. This report fixes what the system means before it says how to build it, in the denotational design style of Conal Elliott. It also requires every decision to be an aggregation in the sense of unified-aggregation-theory (UAT).

1Summary

  • A policy means a committee split into classes, plus a rule on counts. Parties in one class are interchangeable. The rule reads only how many parties in each class approve. A rule that reads only counts is constant on the orbits of the class-preserving permutation group, by construction. UAT then gives existence and uniqueness of the aggregation.
  • Every decision is binary. It lands in the discrete category on Bool. Over a discrete target UAT proves the Schelling-Ising regime is empty, so every decision is in the Arrow-Debreu regime.
  • Amendments pass one at a time, as keep-or-adopt. The current policy's amend rule judges each one. The system never ranks three or more options, so Arrow's theorem (UAT's arrow_impossibility_regime) never applies.
  • A history means a path in a free category. Time is log height, a natural number. The old rule always judges the new rule. This answers Ross's paradox of self-amendment without a fixpoint.
  • ZK, FHE and MPC live only in the implementation. Each one must satisfy one equation against the meaning (a type class morphism) and one view equation for privacy. CKKS satisfies the FHE equation only approximately, so the design excludes it.
  • Without a ledger, quorum intersection prevents forks. Any two sets that the amend rule accepts must share more than f parties. For a plain t-of-n rule this is 2t > n + f.

2Method

Conal Elliott's denotational design starts from meaning, not from mechanism. It has four steps.

  1. Choose a model for each type. The model is a plain mathematical object. It is the specification.
  2. Define each operation by an equation on models. The equations are compositional: the meaning of a compound term comes from the meanings of its parts.
  3. Make the meaning function a homomorphism. If a type claims an algebraic structure (monoid, functor, category, lattice), the meaning function must preserve it. Elliott calls this the type class morphism principle: "the instance's meaning follows the meaning's instance." The laws then hold for the implementation because they hold for the model.
  4. Derive or verify the implementation. The implementation must equal the meaning. Two implementations with the same meaning are interchangeable.

This design uses two meaning functions.

  • ⟦·⟧ gives what the system decides.
  • viewO gives what an observer O learns. Privacy is the requirement that viewO is a function of a declared leakage, up to computational indistinguishability, written ≈.

The second function is the ideal-functionality method of MPC, read as semantics. The ideal functionality is the denotation. A secure protocol is one implementation of it.

What the meaning leaves out

Messages, rounds, network delay, ciphertext noise, key material, signature bytes, gossip and storage. These belong to the implementation. If a choice among them changes a decision, the implementation is wrong.

3What UAT supplies

UAT is a Lean 4 formalization with no sorry and no Mathlib dependency. Its central definition is one line:

Aggregation act F := LeftKanExtension (orbitProjection act) F

Here act : GAction G C is an action of a symmetry group G on a configuration category C. orbitProjection act : C ⥤ C//G sends each configuration to its orbit. F : C ⥤ D is a choice rule. UAT sorts every pair (act, F) into one of three regimes. In Arrow-Impossibility no aggregation exists. In Arrow-Debreu one exists and all of them agree on objects. In Schelling-Ising several exist and two of them differ on some object.

Definition: UAT-respecting

A system respects UAT when every decision it publishes is L.functor.obj ⟨S⟩ for some L : Aggregation act F, where act is a declared group action on the configuration category, the target of F is discrete, and F carries an OrbitConstant proof. By aggregation_obj_eq_rule the published value is then F(S), whatever L the implementation realizes.

Two limits of UAT matter here. First, UAT's Arrow-Debreu regime means object-uniqueness of the aggregation, not the general-equilibrium existence theorem. The UAT README states this limit. Second, UAT has the symmetric group SymmetricGroup n and Z2Group, but not the class-preserving subgroups this design needs (§4). That group action is new work (obligation O1).

Vetoes and named roles

A rule that treats one party differently from the others in its class is not orbit-constant. By UAT no aggregation exists for it. A policy can still give a party a veto or a special role, but it must put that party in a class of its own. The asymmetry is then part of the declared group GP, and every verifier sees it.

5Operations and their meanings

Policy layer

-- per-class approval counts
countP : Approvals P → Counts P
countP S = ( |S ∩ classj| )  for j = 1 .. k

-- the choice rule UAT aggregates
FP : Discrete(Approvals P) ⥤ Discrete Bool
FP = discrete (acceptP ∘ countP)

⟦authorize P a S⟧ = (Lanp FP)⟨S⟩ = acceptP(countP S)

-- an amendment edge exists only when the amend rule accepts
Amendment P P' = { S : Approvals P | amendP(countP S) = true }

⟦nil P⟧        = idP
⟦cons e log⟧   = ⟦log⟧ ∘ ⟦e⟧

policyAt : Nat → Policy
policyAt 0       = P₀
policyAt (h + 1) = target of entry h, an Amendment (policyAt h) P'

countP is invariant under GP: a permutation that keeps each class in place keeps the number of approvers in each class. This one fact discharges UAT's orbit-constancy obligation for every rule. Then aggregation_obj_eq_rule turns the middle term of the authorize equation into the right term, for any aggregation L.

Authorizations do not extend the log. An authorization is a certificate judged at a height h. Only accepted amendments become log entries.

Cryptographic layer

⟦enc pk a⟧            = a
⟦eval g c₁ … cₘ⟧      = g(⟦c₁⟧, …, ⟦cₘ⟧)
⟦share t n s⟧         = s
⟦reconstruct T xs⟧    = s                    when |T| ≥ t
⟦reshare C C' t' xs⟧  = ⟦xs⟧                 same secret, new holders
⟦prove R x w⟧         = R(x, w)
⟦run π x₁ … xₙ⟧       = fπ(x₁, …, xₙ)

View equations

viewO(run π xs)          ≈ SimO(xs restricted to O, fπ(xs))
viewV(prove R x w)       ≈ SimV(x)                   when R(x, w)
viewO(reconstruct T xs)  is independent of s            when |T ∩ O| < t

The first block holds with equality. The view equations hold up to ≈ under named assumptions: the hardness assumption of the FHE scheme, the soundness and zero-knowledge of the proof system, and the corruption bound f.

6Type class morphisms

Each law below says that a meaning function preserves a structure. The implementation inherits the law once it meets the equation in §5.

TCM-A · Equivariance (morphism of G-sets)

⟦authorize P a (σ·S)⟧ = ⟦authorize P a S⟧     for all σ ∈ GP

This is UAT's OrbitConstant, stated as a morphism from approval sets to Bool with the trivial action. It holds for every rule because countP(σ·S) = countP(S).

TCM-B · Lattice of rules

⟦r ∧ r'⟧ = ⟦r⟧ ∧ ⟦r'⟧          ⟦r ∨ r'⟧ = ⟦r⟧ ∨ ⟦r'⟧

Rules combine pointwise on counts. Orbit-constancy, monotonicity, accept(0) = false, accept(n) = true and O4 survive both operations. O5 survives ∧ only: two accepting sets of r ∨ r' can come from different sides and share too few parties. An amendment that builds an amend rule with ∨ must check O5 again.

TCM-C · Circuit homomorphism (FHE)

dec(eval g c₁ … cₙ) = g(dec c₁, …, dec cₙ)     where g = acceptP ∘ countP

Decryption is the meaning function for ciphertexts, and evaluation must commute with it. Exact schemes (BFV, BGV, TFHE) meet the equation while the circuit stays inside the noise budget or is bootstrapped. CKKS meets it only up to an error term, so it would need a per-circuit error bound near the threshold. The design excludes CKKS.

TCM-D · Category of protocols (MPC)

⟦π ∘ ρ⟧ ≈ ⟦π⟧ ∘ ⟦ρ⟧          ⟦id⟧ = id

The meaning of a protocol is its ideal functionality. Canetti's universal composition theorem says this meaning function preserves composition for UC-secure protocols. Each stage in §9 can then be proved alone.

TCM-E · Free category of logs

⟦append log₁ log₂⟧ = ⟦log₂⟧ ∘ ⟦log₁⟧          ⟦nil P⟧ = idP

The meaning of a log is the move from its start policy to its end policy. A verifier can check a log in segments, keep a checkpoint, and resume from it.

7The three regimes in this system

UAT regimeWhere it appears hereBasis
Arrow-Debreu
IsArrowDebreuRegime		 Every authorization and every amendment decision. The target is Discrete Bool and the rule reads only counts. Theorem: aggregation_nonempty_iff_orbitConstant gives existence, aggregation_obj_unique gives uniqueness. Target T1 in §12.
Arrow-Impossibility
IsArrowImpossibilityRegime		 A rule that singles out a party inside its class. A ranked choice among 3 or more amendment options under Pareto and IIA. The policy language cannot express the first. The amendment process never asks the second. Theorem: lan_implies_orbit_constant for the first, arrow_impossibility_regime for the second.
Schelling-Ising
IsSchellingIsingRegime		 Cannot occur for decisions, because the target is discrete. Its analog in the system is a fork: two policies both accepted at one height. A second analog is the set of policies that would ratify themselves, which can have several members. The design never asks for such a fixpoint. Theorem for decisions: not_schelling_ising_discrete. The fork analog is a design reading, not a UAT theorem. O5 and O11 prevent forks.

Why amendments stay binary

Suppose the amend process ranked three or more pending proposals with a rule that is Pareto and IIA. Arrow's theorem forces a dictator. Under the full group Sn that rule has no aggregation, by arrow_impossibility_regime. Under a smaller GP a dictator rule is orbit-constant only if the dictator is alone in a class. O4 then rejects it for any f ≥ 1, because a single approval would be accepted.

The design avoids both outcomes by keeping each decision to two options. For two options, May's theorem says simple majority is the only rule that is anonymous, neutral and positively responsive. A threshold above majority keeps anonymity and monotonicity and gives up neutrality on purpose: denial is the default.

8Self-amendment

Alf Ross asked in 1969 whether a constitution's amendment clause can be used to amend itself. Peter Suber's Nomic is a game whose rules include the rule for changing rules. This design answers the question with time.

  • The amend rule is data. It sits inside P and can change.
  • The old rule judges the new rule. An amendment at height h is judged by amend of policyAt h. The new amend rule applies from height h + 1. No step refers to its own result, so no fixpoint is needed.
  • The type entrenches the invariants. Monotonicity, accept(0) = false, accept(n) = true, O4, O5, the binary discrete target and the count-only rule are fields of the type Policy. A proposal that breaks one cannot be constructed, so nobody can vote on it. There is no entrenchment clause for an amendment to target.
  • Order is part of the meaning. Binary amendments in sequence depend on their order. The meaning of a log is a path, so the order is explicit. This is the cost of avoiding Arrow. §13 lists who controls the order as an open question.
  • Committees can change. A new policy can have a new committee. The implementation then reshares the FHE key and the signing keys, with ⟦reshare⟧ = id on the secret. The view equation for resharing says that, after it, old members' shares tell them nothing about later ballots (proactive secret sharing).

Elliott's functional reactive programming gives the shape of the system's meaning: a behavior, a function from time to value. Here time is log height and the value is the policy. Because policyAt (h + 1) reads only policyAt h and entry h, the definition is causal and total.

9Implementation derived from the meaning

Each stage names the equation it must meet. The stages run in this order for one decision.

  1. Key setup MPC

    The committee runs distributed key generation for a threshold FHE key.

    ⟦dkg⟧ = (pk, share t n sk)     fewer than t parties learn nothing about sk

  2. Ballot FHE + ZK

    Party i encrypts its bit vi, binds it to the height h and the digest of the request or of P′, signs it, and proves Rballot.

    ⟦ci⟧ = vi

  3. Tally FHE

    Anyone evaluates the rule on the ciphertexts. A missing ballot is the trivial public encryption of 0, so a missing ballot can only lower the count.

    cout = eval (acceptP ∘ countP) c₁ … cₙ       ⟦cout⟧ = acceptP(countP S)   by TCM-C

  4. Threshold decryption MPC + ZK

    t parties publish partial decryptions with proofs Rdec. Anyone combines them into the bit b. Partial decryptions must be simulatable from b alone, and the implementation adds noise flooding for this.

    b = ⟦cout⟧        view(partials) ≈ Sim(b)

  5. Certificate

    An authorization certificate is (h, a, ballots, proofs, b). For an amendment with b = true, the same data plus P′ becomes log entry h + 1. It holds the hash of entry h and the signatures of an accepting set.

  6. Verification

    A verifier reruns stage 3, checks the proofs and signatures, and checks that P′ is a well-typed Policy.

    verify accepts c  ⇔  c denotes a valid step

ZK relations

Rballot( x = (pk, h, d, c) ; w = (v, r) ) :
    c = Encpk(v ; r)   and   v ∈ {0, 1}
    -- the signer's membership in policyAt h is checked in public

Rdec( x = (pk, cout, dᵢ, vkᵢ) ; w = (skᵢ, e) ) :
    dᵢ = partial decryption of cout under skᵢ with flooding noise e
    and   e is in the allowed range   and   skᵢ matches vkᵢ from key setup

The policy is public, so its invariants need no ZK. A verifier checks O3 to O5 directly on the finite set of minimal accepting count vectors.

10Off-chain consequences

  • No shared clock. Time is log height h : Nat, not wall-clock time.
  • One entry per height. Honest parties sign at most one entry per height. Two entries at one height need two accepting sets. By O5 they share more than f parties, so some honest party signed both, which is a contradiction. The log is therefore a list, not a tree, and policyAt is a function.
  • Equivocation is provable. Two signed entries at one height from one party are transferable evidence of misbehavior.
  • Freshness needs a read set. For a plain t-of-n amend rule, a verifier asks a set R of at least n − t + f + 1 parties for their latest entry. Every accepting set W shares at least f + 1 parties with R, so some honest party in R signed the latest entry and can show it. The verifier takes the highest height it can verify. A faulty party can withhold, but it cannot show a higher verified height that does not exist.
  • Availability is outside the meaning. Entries must be retrievable. Replication among committee members is an implementation choice.

12Lean sketch

A sketch of the model on top of UAT. It is not compiled. UAT names are ChoiceRule, Discrete, GAction, SymmetryGroup, OrbitConstant, Aggregation and IsArrowDebreuRegime. Every other name is new.

import UnifiedAggregation
open UnifiedAggregation CompCatTheory

structure Committee where
  k    : Nat
  size : Fin k → Nat

/-- One approval bit per party, indexed by class. -/
abbrev Approvals (c : Committee) : Type :=
  (j : Fin c.k) → Fin (c.size j) → Bool

/-- Approvals per class: the orbit invariant of the class-preserving group. -/
def count (c : Committee) (S : Approvals c) : Fin c.k → Nat :=
  fun j => (List.finRange (c.size j)).countP (fun i => S j i)

structure Rule (c : Committee) where
  accept      : (Fin c.k → Nat) → Bool
  monotone    : ∀ a b, (∀ j, a j ≤ b j) → accept a = true → accept b = true
  rejectsNone : accept (fun _ => 0) = false
  acceptsAll  : accept c.size = true

-- Signatures only.  Bodies are obligations O1, O4, O5.
-- young       : Committee → SymmetryGroup.{0}
-- youngAction : (c : Committee) → GAction (young c) (Discrete (Approvals c))
-- choice      : (c : Committee) → Rule c →
--                 ChoiceRule (Discrete (Approvals c)) (Discrete Bool)
-- quorumSafe  : (c : Committee) → Rule c → Nat → Prop
-- forkFree    : (c : Committee) → Rule c → Nat → Prop

structure Policy where
  committee : Committee
  authorize : Rule committee
  amend     : Rule committee
  faults    : Nat
  safeAuth  : quorumSafe committee authorize faults
  safeAmend : quorumSafe committee amend faults
  noForks   : forkFree committee amend faults

structure Amendment (P P' : Policy) where
  approvals : Approvals P.committee
  accepted  : P.amend.accept (count P.committee approvals) = true

inductive Log : Policy → Policy → Type where
  | nil  (P : Policy) : Log P P
  | cons {P P' Q : Policy} : Amendment P P' → Log P' Q → Log P Q

def Respects (c : Committee) (r : Rule c) : Prop :=
  OrbitConstant (youngAction c) (choice c r)

Theorem targets

  • T1 Respects c r → IsArrowDebreuRegime (youngAction c) (choice c r). From aggregation_nonempty_iff_orbitConstant and aggregation_obj_unique. The universes line up: the group, the configuration type and Bool all live in Type.
  • T2 ∀ r : Rule c, Respects c r. From invariance of count under young c. With T1, every rule the type admits is in the Arrow-Debreu regime.
  • T3 Two approval sets accepted by an amend rule with forkFree share more than faults parties. With a model of single signing, this gives one entry per height.
  • T4 Log.append with nil as identity and associativity: the category laws behind TCM-E.

13Open questions

  • The output leaks what the rule implies. Under unanimity, b = true reveals every vote. This is part of the ideal functionality, so no implementation can hide it. Choose rules with this in mind.
  • Committee loss can freeze the system. If fewer parties are live than the smallest accepting set of the amend rule, no amendment can pass. A recovery rule needs a clock, and an off-chain system has none it can trust. Undecided.
  • Stale certificates. A certificate judged at height h stays checkable after an amendment at h + 1 removes a party. Consumers need a freshness rule, for example "the height must equal the latest verified height" (§10). Undecided.
  • Agenda control. Whoever collects ballots chooses which proposal goes to a vote first. McKelvey (1976) showed how much an agenda setter can do under majority rule in more than one dimension. The log records the order but does not make it fair. Undecided.
  • Receipts. A party can prove its vote by revealing its encryption randomness. ZK and FHE give ballot secrecy, not receipt-freeness. If coercion matters, the ballot stage needs more machinery, such as re-randomization with a designated-verifier proof.
  • Exact and approximate meaning. The decision equations are exact and a Lean proof can cover them. The view equations hold up to ≈ and need a computational model that UAT does not have.
